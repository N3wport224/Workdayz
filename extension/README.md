# Workdayz browser extension

Fills in a Workday job application from a resume/cover letter package
generated by the [Workdayz web app](../web). Runs inside your own
already-authenticated browser tab — it never stores or handles your Workday
login credentials, and it never clicks Next/Continue/Submit for you. You
drive the wizard; the extension just fills in whatever fields it can find on
the step you're currently on.

## Build

```bash
npm install
npm run build      # outputs to dist/
npm run watch       # rebuild on change, for development
```

## Load it in Chrome / Edge

1. Go to `chrome://extensions` (or `edge://extensions`).
2. Enable "Developer mode".
3. Click "Load unpacked" and select the `extension/dist` folder.

## Connect it to the web app

1. Open the extension popup and enter the web app's URL (default
   `http://localhost:3000`), then click **Connect**. This requests
   permission for that one origin and registers a bridge content script
   there — the extension only gets access to the exact origin you approve.
2. Reload the web app tab. The `/apply` page should now show "Extension
   status: detected".

## Using it

1. On a Workday job posting page, click the floating **Tailor with
   Workdayz →** button. It scrapes the title/description and opens the web
   app's `/apply` page with them pre-filled.
2. In the web app, review the tailored resume, cover letter, and ATS score,
   then click **Send to extension for Workday autofill**.
3. Go back to the Workday tab (or start the application from the job
   posting) and click **Autofill this step** — either the floating widget or
   the extension popup's "Autofill active tab" button both work.
4. Review what got filled, click Next yourself, and re-run autofill on the
   next step. Nothing is submitted automatically — you click the final
   Submit button when you're satisfied.

## How field matching works, and its limits

Workday tenants heavily customize field labels, layout, and which
`data-automation-id` attributes are present, so this doesn't hardcode CSS
selectors for a specific tenant. Instead `src/content/dom-utils.ts` does
fuzzy, synonym-based matching against each field's label (via `<label>`,
`aria-label`, `aria-labelledby`, placeholder, and nearby heading text).

This means:
- It generally handles the flat "My Information" contact fields (name,
  email, phone, address) and resume/cover-letter file uploads well.
- Repeatable multi-entry sections (work history, education) are **not**
  auto-expanded/added in this version — if your tenant's application form
  has an "Add" button for each job, you'll still need to click Add yourself
  and fill or copy-paste entries beyond what's already visible on the page.
- Some tenants use custom domains that don't match `*.myworkdayjobs.com` —
  if the widget doesn't appear on your company's application pages, add
  your tenant's domain to `host_permissions` and the `content_scripts`
  `matches` array in `manifest.json`, then rebuild.
- If a field isn't found, it's silently skipped and listed in the "couldn't
  find" summary rather than guessed at — check your company's IT/acceptable
  use policy before relying on this for real applications.

## Project layout

```
src/
  types.ts                  # shared types + message protocol (mirrors web/lib/types.ts)
  background/background.ts  # service worker: storage, dynamic content-script registration
  content/
    workday.ts               # entry point injected on Workday pages; mounts the floating widget
    job-scraper.ts            # scrapes title/company/location/description from a posting page
    autofill.ts                # fills the current step's fields from a stored package
    dom-utils.ts                # label-matching + value-setting + file-attach helpers
    web-app-bridge.ts            # dynamically registered on the connected web app origin only
    widget.ts                     # shadow-DOM floating panel UI
  popup/popup.html, popup.ts    # toolbar popup: connect web app, status, manual autofill trigger
```
